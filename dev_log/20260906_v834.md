## 查实并修复（11 项 + 1 项测试纪律）
### H1 [P1] 协调看板自诞生起从未打开过（QTableWidgetItem 未导入）
- ide_extras.py 的 refresh() 用 QTableWidgetItem，模块级 import 与 __init__ 局部 import 都没有它；
  __init__ 末尾即调 refresh() → NameError → 命令面板点「全局协调看板」直接抛异常。
- v8.33 的 py_compile 与 coordination 数据层单测（8 断言）都抓不到——正是 FreqErr
  「Qt 控件 API 要看准类属」「功能写好未接线」同族。
- 修复：补 import；顺带修错误分支里 setRowCount(0)→setRowCount(1) 的冗余写法。
- 回归：新增离屏「构造 + show + 刷出数据行 + 读回单元格」断言（复用 QApplication 单例，
  排在 test_gui 之后，避免二次构造崩）。

### H2 [P2] 纯心跳不落盘 → 看板看不到"没声明资源"的 Agent
- touch() 的落盘条件是 new_conflicts or not throttle or changed；agent.py 轮开始的 touch
  只带 status/model → 三者全 False → **连新建条目都不写盘**。结果：看板只显示声明过外部资源
  或调过 declare 的 Agent，违背用户裁决「检查每一个正在并发执行任务的 agent 都在做什么」。
- v8.33 原测试每次都带 task/resources，所以全绿。
- 修复：加 _LAST_PERSIST 记账，落盘条件补 created（首次登记）与 due（距上次落盘超节流窗口）；
  写盘频率仍受 _TOUCH_THROTTLE_S=8s 约束。

### H2b [P2] 轮开始不带 task → 「在干什么」列恒为（未声明）
- 修复：agent._build_system_prompt 的 touch 带上 self._todo_text（截 300 字）——本轮用户消息/
  专家子任务即为"在干什么"，人类不必等 AI 自愿 declare 就能看到。

### H3 [P2] 看板对话框常驻不销毁 + 5s 定时器永不停
- 对话框以主窗口为 parent、无 WA_DeleteOnClose → 每开一次残留一个隐藏实例，其 5s 自动刷新
  定时器持续读盘（FreqErr「非模态 dialog 不销毁」「定时器成对管理」同族）。
- 修复：setAttribute(Qt.WidgetAttribute.WA_DeleteOnClose) + finished 信号停表。
  注：我第一版写成 Qt.WA_DeleteOnClose（PyQt5 形式）→ 新断言当场抓到 AttributeError，
  已改 scoped 枚举。

### H4 [P2] TTL 回收只改内存不回写 → coordination.json 只增不减
- _purge() 只删内存 dict，snapshot() 只 return 不 _save → 死 Agent 与其收件箱在磁盘上永久堆积
  （每次进程重启多一个「目录名@新pid」键，inbox 每键最多 50 条消息）。
- v8.33 的 TTL 断言只检查 snapshot 返回值 → 看不出磁盘泄漏。
- 修复：_purge 返回回收条数；snapshot 与 touch 据此 _save；回收时连带清理该 Agent 的 inbox 与
  _LAST_PERSIST 记账。语义无损：Agent 复活后重新声明资源会再次触发双向投递。
- 回归：断言读**磁盘终态**（_load() 后查 agents/inbox 键），不再只看返回值。

### H5 [P3·UX] 被禁用的模式勾选没有理由提示
- v8.32 我给三个模式勾选加了 setEnabled(False)，但用户只看到"点不动"，不知道为什么。
- 修复：禁用态挂 tooltip「三大模式总开关已关闭（模块开关页 ENABLE_MODES）；先打开总开关，此处勾选才生效」。

### H6 [P3·UX] 协调看板只藏在命令面板里
- 唯一入口是 Ctrl+Shift+P 命令面板——用户根本发现不了这个"损害发生前叫停"的闸口。
- 修复：菜单栏「工作区 → 全局协调看板…」加入口（带 tooltip）。

### H7 [P3·UX] 看板 Agent 列无法定位到窗口
- Agent 列只有「目录名@pid」，同名目录/多进程时人类分不清该去叫停哪一个。
- 修复：Agent 单元格挂完整工作区路径 + pid 的 tooltip。

### H8 [P2·UX] webui 人类看不到协调看板
- v8.33 只给了 GET /api/bridge/coordination 端点 + AI 工具 coordination_board；网页端用户想知道
  "谁在动我的服务器"只能去问 AI——与用户裁决「这两个信息也有必要让用户能看到」不符。
- 修复：设置「安全中心」页新增「全局协调看板」只读区块（进入页面自动加载 + 手动刷新 +
  冲突计数状态行）。渲染走 textarea.value 与 textContent，天然规避 innerHTML 注入（FreqErr #152）。
- 顺带：panels.js 改动 → index.html ?v= 统一 bump 8.34.0（17 处，残留 0）+ node --check 过。

### H9 [P3·UX] 看板文案承诺了界面做不到的事
- 原文「人类可在损害发生前直接叫停对应 Agent」，但看板没有任何叫停控件（跨进程也无从叫停）。
- 修复：文案改为可操作指引——「要叫停某个 Agent：鼠标停在 Agent 列看它的工作区路径，切到那个窗口点『停止』」。

### H10 [P2·UX] 监控看板用模态，挡住本窗口的「停止」
- dlg.exec() 模态：用户看到冲突却点不到本窗口的停止按钮，与看板用途直接相悖。
- 修复：改 show() 非模态 + 单实例复用（二次打开 raise_/activateWindow；捕获 RuntimeError 处理
  WA_DeleteOnClose 已销毁的包装器）。
- 回归：gui 级断言走真实入口（可见 + 非模态 + 二次打开复用同一实例）。

### H11 [P3] 轮结束状态不置 idle（v8.33 自述边界收口）
- v8.33 dev_log 自述「轮与轮之间 status 保留 running 至 TTL 过期」——人类看板因此无法区分
  "正在跑"与"跑完了"，叫停判断失去依据。
- 修复：Agent._coord_idle()（仅顶层 Agent，防子 Agent 抖动），run() 与 _run_experts() 收尾各调一次。
