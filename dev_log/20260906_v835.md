## 改动清单
### A. 逐专家看板 + 意图字段语义
- coordination.py 新增 `agent_uid(workspace, sub)`：顶层=「工作区名@pid」；专家/子Agent 追加
  sub_label 身份后缀（"/"消毒、截 40 字），逐专家单独成行、各自收件箱——同一轮专家团的每个
  专家在看板上是独立条目，冲突消息精准投递到对应专家。
- agent.py 新增 `_coord_uid()`；轮开始 touch / pop_inbox / _coord_idle 全部改用 uid。
- task 字段=「准备做什么事情」：主 Agent=本轮用户消息，专家=其分到的任务（_todo_text）。
- tools.py run_command 嗅探：只登记资源，**不再用原始命令覆盖「接下来」**（命令是"手上在执行的"，
  意图字段留给 declare 与轮开始登记——用户裁决原话）。
- _coord_idle 语义拆分：顶层置 idle、专家/子Agent 置 done（保留至 TTL 自然回收供回看）。

### B. 冲突给人类发消息（coordination 事件）
- 新事件类型 coordination：note=conflict_note()（资源键 + 对方 agent_id/工作区/**准备做什么** +
  错峰与用户确认要求）。gui 三分支同源接线：_handle_event（chat.ai_note 气泡）、
  chat.sub_event（专家包装路径，带「专家·X」前缀）、CLI _render（黄字）——FreqErr #55
  「新增事件必须同步为所有渲染入口补分支」逐条落实。
- 去重：同一 run 内同一组冲突键只报一次（_coord_notified 按 key 集合去重，键集合变化再报）；
  run() 每轮开头重置，防跨轮残留误报。
- 触发点：agent.run() 每轮 system 构建后 await _coord_notify()（_build_system_prompt 是同步方法，
  冲突在轮开始检测后挂实例、主循环转事件）。

### C. 摄像头 Agent 排查（字面检查）
- 全仓 grep：摄像头/camera/VideoCapture/webcam/cv2/getUserMedia **零命中**；Future.md 无立项。
- 仓库内唯一的"独立 Agent"= 悬浮助手「小龙」（webui/app/voice_pet_host.py + webui/static/js/voice-pet.js）：
  纯 Web Speech（STT 麦克风 + TTS），无任何摄像头/视觉能力。
- 小龙过查（读码结论）：宿主端端点全部开关+登录双保护、字段白名单、长度/数量上限、NaN 防护、
  同步 IO 走线程池、共享锁防任务文件竞态——干净；前端 appendMessage/renderConversations 走
  textContent（无 innerHTML 注入面，FreqErr #152 达标）、模式判定 JSON 解析失败有 chat 兜底、
  agentPauseMain/ResumeMain 成对。
- 顺手加固：renderTaskProgress 的 summary 值数字归一（Number()）后再进 innerHTML（防御面收紧）。
- 结论：摄像头能力不存在。若要给小龙加摄像头（getUserMedia 抓帧 → 多模态模型），涉隐私与
  传输面，需用户单独裁决——见遗留。
