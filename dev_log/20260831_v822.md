# v8.22 基础能力补齐：Agent 记忆 / 出关审核 / 外部 API 清单 / Heartbeat 泄露检查

日期：2026-08-31 | 版本：8.22.0 | 范围：webui（前端 + 后端）

## 背景

用户要求补齐基础向核心能力（记忆、经验），再谈复杂功能：
1. 基础 Agent 记忆/经验系统（跨会话）
2. AI 向外传递内容前必须 repeat 要求、经审核出关
3. 用户可维护授权给 AI 的外部 API 清单，使用时 Agent 找用户授权
4. 一键 heartbeat 泄露检查（API 厂商 + 本地项目）+ SMTP 发件

## 变更清单

### 模块1：Agent 长期记忆（memory）
- 新增 `webui/static/js/memory.js`：Memory 模块（IndexedDB 'memory' store，DB v2→v3 升级）。
  - 四类记忆：fact（事实）/ lesson（经验教训）/ pref（用户偏好）/ skill（技能要点）。
  - 检索：本地打分（标题×3 + 标签×2 + 内容×1 token 命中 + bigram 相似度），零 API 成本。
  - 容量控制：MAX_TOTAL 2000 条，超限按 LFU 淘汰；同标题合并更新保留命中计数。
- `core.js`：IDB 升 v3 增加 memory store；ENABLE_MEMORY / ENABLE_OUTBOUND_GATE 配置项（默认开）。
- `tools.js`：memory_save / memory_search / memory_list / memory_delete 四工具 + 开关裁剪。
- `agent.js`：runSession 每轮开始按用户消息召回 top-5 注入 system 上下文；系统提示词加记忆规范
  （踩坑修复后必须沉淀 lesson、动手前先查经验）。
- 检修：上下文守门重建 messages 时不再丢失记忆召回注入（memText 重新追加）。

### 模块2：出关审核（repeat 机制）
- `tools.js`：outbound_deliver 工具——AI 必须逐字复述用户原始要求（requirement）+ 给出完整内容
  （content），经用户批准后出关。target：clipboard / file / email。
  - email 目标存为草稿（localStorage），AI 不能直发邮件；发送由用户在安全中心手动触发。
  - 出关审核不走 approval_mode 分级，永远强制用户确认。
- `chat.js`：审批卡片扩展 outbound 类型（shield 图标 + 需求复述框 + 内容预览框）。
- `agent.js`：系统提示词加出关规范（最终交付物禁止直接写在聊天回复里出关）。

### 模块3：外部 API 清单
- `core.js`：ExtAPIs 模块（localStorage 存储；upsert 校验 name 格式 + base_url 必须 http(s)）。
- `tools.js`：api_request 工具——查清单 → 未知名称返回可用清单；首次调用某 API 弹授权卡片
  （会话内记住）；实际请求走后端 /api/llm/ext_proxy。
- `proxy.py`：新增 POST /api/llm/ext_proxy——复用 _validate_base 全套 SSRF 防护
  （数值 IP 归一/内网封锁/自环检测）；方法白名单；path 禁控制字符（防头注入）；
  请求体 ≤2MB、payload ≤1MB、响应回传 ≤512KB；错误经 _sanitize_error 脱敏。
- `chat.js`：api_call 授权卡片（globe 图标 + API/方法/路径/请求体预览）。
- `panels.js`：安全中心新增「外部 API 清单」编辑器（增/删，密钥只存浏览器本地）。
- `icons.js`：新增 globe / brain 图标（内联 SVG，无 emoji）。

### 模块4：Heartbeat 泄露检查 + SMTP
- `server.py`：
  - POST /api/security/leak_scan：本地工作区敏感凭证扫描（8 类模式：OpenAI/Anthropic/AWS/
    GitHub/Google/Slack Key、私钥块、配置凭证；命中脱敏回显前 8 字符）+ API 厂商 HEAD 心跳
    （内网/环回地址标非法，复用 proxy SSRF 校验器）+ 可选 SMTP 报告邮件。
    扫描上限：20000 文件 / 单文件 2MB / 200 条发现；跳过 node_modules/.git/backups/data 等。
  - GET /api/security/smtp_status：SMTP 配置状态探测。
  - 审计日志记录 leak_scan 动作。
- `mailer.py`：新增 send_text_email 通用文本邮件（SSL 同通道；防头注入；长度上限）。
- `panels.js`：安全中心新增「Heartbeat 泄露检查」一键检查卡片（收件邮箱可选）+
  「出关草稿」查看器（邮件客户端发送/复制/删除）。

## 教训
- llm_allow_loopback 默认 True（本地 LLM 设计），SSRF 测试断言应选「始终封禁的内网地址」
  而非环回地址，否则断言与开关状态耦合。
- 上下文守门这类「重建 messages」的机制会静默丢弃此前注入的附加 system 段（记忆/依赖树警告），
  新增注入点必须检查所有重建路径。
