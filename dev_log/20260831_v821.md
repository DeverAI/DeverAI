## 三、阶段C：WorkTree 入口对齐（UI + 设计 + 后端）

### 3.1 后端端点（webui/app/bridge.py）

- Fact.md 裁决：`bridge_workspace` 全局单例。WorkTree = git worktree（同仓库多工作树），
  切换 = 改 `bridge_workspace` 指向某 worktree 路径。
- 路径限定 `<workspace>/.worktrees/<name>`（防任意路径写入）。
- 四个端点：
  - `GET /worktree/list`：只读，无审批。`git worktree list --porcelain` 解析，
    返回 `[{name, branch, head, dirty, current}]` + `count`。
  - `POST /worktree/create`：需 danger_ok。`git worktree add <path> <branch>`。
  - `POST /worktree/switch`：需 danger_ok。改 `bridge_workspace` 指向。
    name 为主工作树 codename（不切）或 `.worktrees/<name>`。
  - `POST /worktree/remove`：需 danger_ok。`git worktree remove <path>`，
    不能移除当前工作树。
- 安全：`_readonly_block` + `_strict_bool(danger_ok)` 严格审批门，
  name 正则 `[A-Za-z0-9_.\-]{1,64}` 防注入。

### 3.2 前端 UI（panels.js + index.html）

- 右栏新增 WorkTree Tab（与 Summary/Terminal/Files 并列）。
- `WorkTreePanel.refresh()`：调 `/api/bridge/worktree/list`，渲染工作树列表。
  - 当前工作树高亮（`.wt-item.current`，accent 边框 + accent-dim 背景）。
  - 每项显示 name / branch / head / dirty 标记 / current 标记。
- `_switch(name)`：confirm 确认后调 `/api/bridge/worktree/switch`，
  成功后 `FS.refreshRoot()` 刷新文件树 + `WorkTreePanel.refresh()`。
- 顶部按钮：刷新（`#btn-wt-refresh`）/ 新建（`#btn-wt-new`）。
- 提示条 `#wt-hint`：解释 WorkTree 机制（同仓库多工作树并行检出）。

### 3.3 AI 上下文注入（agent.js + tools.js）

- `buildSystemPrompt()` 增 WorkTree 提示行：
  `'- WorkTree: 当前工作区支持 git worktree（同仓库多工作树）。可用 worktree_list 查看所有工作树，worktree_switch 切换（需用户审批）。'`
- tools.js 新增两个工具定义 + 实现：
  - `worktree_list`：只读，无审批。调 `/api/bridge/worktree/list`，格式化输出。
  - `worktree_switch`：需用户审批。调 `/api/bridge/worktree/switch`，
    `danger_ok: true` 由前端审批流注入。
- AI 可感知工作树状态 + 主动切换，与 UI 入口对齐。

## 五、关键设计决策

1. **Peek 式而非 Overlay 式**：展开挤占主区而非覆盖，避免遮挡内容，
   符合 ChatGPT 桌面端「未碰最简、碰了展开」的语义，但保留主区可见性。
2. **cream 暖米而非冷灰**：纸张感暖中性（#faf6ec 系），与黑（dark）/白（light）
   构成三色，accent 用琥珀棕（#b45309）保持暖色系一致性。
3. **WorkTree 单例工作区 + 多工作树**：Fact.md 裁决 bridge_workspace 全局单例，
   WorkTree 切换 = 改单例指向，不并发多树。UI/AI/后端三层入口对齐。
4. **danger_ok 审批门统一**：worktree/switch + worktree/remove + worktree/create
   均走 `_strict_bool(danger_ok)` 严格布尔校验，与既有 run_command 危险命令审批同源。
