# dev_log 2026-09-06 v8.33 — 全局协调协议（跨工作区 Agent 闸口）

## 背景（用户裁决）
「加一个全局的闸口：检查每一个正在并发执行任务的 agent 都在做什么；发现冲突就让两个 agent 互通信息——你在干什么？我在干什么？你接下来要干什么？我接下来要干什么？这两个信息人类也要能看到，在损害发生前直接阻止，而不是等事后兜底。」场景=跨工作区外部资源并发：两个不同工作区的 Agent 同时 SSH 同一服务器，一个重启、另一个上传中掉线还懵着。工作区内已有租约锁/文件分区，跨工作区外部资源是空白层。

## 改动清单
### A. pyqt/desktop/coordination.py（新模块，无 Qt）
- 注册表 `data/coordination.json`（本机 DeverAI 进程共享 DATA_DIR，跨工作区天然互通）：agents（workspace/pid/status/task/resources/next_action/model/last_seen）+ inbox（逐 Agent 收件箱）。
- 心跳 TTL 180s（`DEVERAI_COORD_TTL_S` 可覆盖，`_KEEP_OVERRIDE` 测试钩子）；轮开始/命令调用节流刷新；过期自动回收（GUI 关闭自然过期）。
- 冲突检测：归一化资源键（`norm_resource` 统一剥 `x://` 与 `ssh:` 裸前缀——收口修复"ssh:mindog vs ssh://mindog 不相等"）；两个存活 Agent 同键 = 冲突。
- 协议互通：检测到新冲突 → **双向投递收件箱消息**（对方在干什么/我要干什么/下一步 + 协调要求）；`pop_inbox`（轮开始注入，读后清空）/ `send`（直投）。
- `resources_from_command`：命令嗅探 ssh/scp/rsync/sshpass/plink 主机（忽略 127.0.0.1/localhost）。
- `snapshot`（看板：存活 Agent + 冲突对）/ `touch`（登记+心跳+冲突检测）/ `render_protocol_block`（注入块）。

### B. 工具与提示词（tools.py / agent.py）
- `coordination_board`（只读看板，chat 形态可用）/ `coordination_declare`（声明任务/资源/下一步 → 即时返回冲突+收件箱）；TOOL_FUNCS/build_tool_defs/TOOL_MATCH 三处注册；`ENABLE_COORDINATION` 三层贯通（config/SWITCHES/defs 门控）。
- `COORDINATION_RULES` 提示词：操作外部资源前必须 declare；冲突错峰；破坏性远程操作必经用户确认；轮开始注入收件箱+冲突快照（`render_protocol_block`）。
- `tool_run_command` 自动嗅探命令中的 ssh/scp/rsync 主机并登记（冲突下一轮注入 + 看板可见）。

### C. 人类看板（ide_extras.py / gui.py / webui）
- 桌面 `CoordinationBoardDialog`（表格：Agent/状态/在干什么/外部资源/接下来/最近活跃；冲突行红底高亮；5s 自动刷新）——命令面板「全局协调看板」入口。
- webui `GET /api/bridge/coordination`（只读快照）+ tools.js `coordination_board` 工具（命令桥授权门控）；index.html `?v=` 全量 bump 8.33.0。
