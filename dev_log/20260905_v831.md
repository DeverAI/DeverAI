## 查实并修复（3 项）
### F1 [P2] shutil.copy2 保留源 mtime → drift minimal 增量丢文件
- sync.build_drift_upload minimal 按 `mtime > 上次推送基准` 筛文件；copy2 把源文件的旧 mtime
  原样带到 uploads/，用户拖入的旧文件**永远进不了增量包**——服务器续算端工作区缺文件，
  manifest 又包含它所以差集清理也不会提示，静默缺失。
- 修复：改 `shutil.copy`（新 mtime）。回归断言：源文件 utime 到 2020 → 入库后 dest mtime > 2023。
### F2 [P3] checkpoint 的 uploads 跳过大小写敏感
- Windows 大小写不敏感，AI 写 `Uploads/x.txt` 与 `uploads/x.txt` 同目录，原实现可绕过 C 盘约束。
- 修复：lower() 后比较（save_checkpoint / save_checkpoint_bytes 两处）。回归断言：`Uploads/a.txt` 返回 None。
### F3 [P3] 先 stat 后 copy 的 TOCTOU 窗口
- 拷贝中的下载/日志类源文件可在检查后变大，超限内容照常入库。
- 修复：拷后复核 dest 大小，超限删半截并拒绝。（不可稳定离屏模拟，无断言，防御性修复）
